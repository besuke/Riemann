# 債券の仕様（P2、草案）

P2 では、固定利付債のキャッシュフロー、経過利子、価格と利回り、割引を作る。QuantLib の仕様に依拠し、QuantLib R バインディング 1.42 の実行結果と照合する。進め方は、仕様書（[specification.md](specification.md)）の 10 章と同じく、小さく分けて照合しながら広げる。

記述の区分（【ソース確認】【実行照合済み】【設計案】）は仕様書と同じである。

| 段階 | 内容 | 状態 |
|---|---|---|
| P2-1 | 固定利付債のキャッシュフロー（クーポン・償還）、受渡日、額面、経過利子 | 2026-10-31 照合済み（2 章） |
| P2-2 | 利回りと価格（複利・単利・連続、クリーン・ダーティ）、デュレーション、コンベクシティ、BPV | 2026-10-31 照合済み（3 章） |
| P2-3 | 割引カーブによる評価（ゼロカーブ・フラットカーブ） | 2026-10-31 照合済み（4 章） |
| P2-4 | 日本式の単利利回り（GaussQuant の `bond_*_YEN_GQL`、LagrangeFinance II-1） | 2026-10-31 照合済み（5 章） |

## 1. QuantLib の仕様【ソース確認】

参照：QuantLib `70f240f`（照合の正は R バインディング 1.42 の実行結果）。v1.42 からの差分を読んだ範囲では、以下の結果に関わる変更は見当たらなかった（`cashflows.cpp` は `coupon_cast` への置き換えと BPS 計算の書き方の整理、`cashflow.cpp`・`event.cpp`・`bond.cpp` は `std::optional` への置き換えなど）。

| 項目 | QuantLib の仕様 | ソース |
|---|---|---|
| クーポンの額 | `nominal * (compoundFactor - 1.0)`。単利なら `compoundFactor = 1 + r t`、t は日数計算の年数割合 | `cashflows/fixedratecoupon.cpp`、`interestrate.cpp` |
| 参照期間 | 途中の期間は計算期間と同じ。最初の期間が規則どおりでなければ、参照期間の開始を「終了日から 1 期間前」（スケジュールのカレンダー・規約・月末の扱いで計算）にする。最後の期間が規則どおりでなければ、参照期間の終了を「開始日から 1 期間後」にする | `FixedRateLeg::operator Leg` |
| 支払日 | 計算期間の終了日を、支払カレンダー（指定がなければスケジュールのカレンダー）と支払の営業日調整で調整した日 | 同上 |
| 償還 | 額は `(償還率 / 100) * 額面`。日付は最後のクーポンの支払日。日付で安定ソートし、同じ日付ならクーポンの後 | `bond.cpp`（`addRedemptionsToCashflows`、`calculateNotionalsFromCashflows`） |
| 受渡日 | 評価日から受渡日数だけ営業日を進めた日（0 日なら Following で調整）。発行日より前にはしない | `Bond::settlementDate` |
| 額面 | 償還日より前は額面、償還日以後は 0 | `Bond::notional` |
| 発生済みの判定 | 基準日を含めない（既定）なら、支払日 ≤ 基準日で発生済み。グローバル設定 `includeTodaysCashFlows` で変わりうる | `cashflow.cpp`、`event.cpp` |
| 経過利子 | 受渡日に発生済みでない最初のキャッシュフローの支払日について、その日に支払われるクーポンの経過利子を合計し、額面 100 当たりにする。額面が 0 なら 0 | `CashFlows::accruedAmount`、`BondFunctions::accruedAmount` |

## 2. 実装と照合結果（P2-1）

### 2.1 実装

- `cashflows.rs`：`FixedRateCoupon`（支払日、額面、利率、日数計算、計算期間、参照期間）、`CashFlow`（クーポン・償還）、レグを作る `fixed_rate_leg`、経過利子 `accrued_amount`。クーポンの額は QuantLib と同じ計算順（`N * ((1 + r t) - 1)`）で求める。
- `instruments/fixed_rate_bond.rs`：`FixedRateBondSpec` から `FixedRateBond::new` で債券（スケジュールとキャッシュフロー）を作る。`settlement_date(評価日)`、`notional(日付)`、`accrued_amount(受渡日)`。
- QuantLib との違い：
  - 評価日は引数で渡す（グローバル設定を使わない）。
  - 受渡日当日のキャッシュフローを含めるかどうかは引数で渡す（既定は QuantLib の既定と同じく含めない）。
  - 利率と額面は 1 つ。償却、ex-coupon、支払ラグは扱わない。
- 処理は QuantLib から移したものとして扱い、各ファイルの先頭と `THIRD_PARTY_NOTICES` に移植元と著作権表示を書いた。

## 3. 利回りと価格（P2-2）

### 3.1 QuantLib の仕様と版の違い【ソース確認】

照合の正である v1.42 と、仕様を読んだ `70f240f` で、利回りによる評価の計算が変わっていた。Riemann は v1.42 に合わせた。

| 項目 | v1.42（Riemann が合わせた版） | `70f240f` |
|---|---|---|
| 現在価値（`CashFlows::npv`） | 区間ごとの割引係数の積 | 同じ（共通の `cashFlowResults` に整理） |
| デュレーション・コンベクシティ | 累積した時間 t に対する割引係数 `discountFactor(t)` | 区間ごとの割引係数の積と、その微分 |
| 内部収益率（`IrrFinder`） | 目的関数は「目標値 − NPV」、NewtonSafe に渡す微分は修正デュレーションそのもの | 目的関数は「NPV − 目標値」、微分は「−修正デュレーション × NPV」 |
| 混合の複利（SimpleThenCompounded など） | 時間で単利と複利を切り替える | 直接の計算は不可（キャッシュフローの関数側で扱う） |

最初は `70f240f` の `IrrFinder` の形で実装し、利回りが QuantLib（v1.42）と最後の桁まで一致しなかった。v1.42 の形に直したところ一致した。

その他の仕様（v1.42、`bondfunctions.cpp` は `70f240f` でも同じ）：

- ダーティ価格 = 受渡日に発生済みでないキャッシュフローの、利回りによる現在価値 × 100 ÷ 額面。クリーン価格 = ダーティ価格 − 経過利子。
- 利回り：価格（クリーンなら経過利子を足す）を額面当たりにし、NewtonSafe で解く。精度 1e-10、最大 100 回、初期値 5%、最初の区間幅は初期値の 1/10。解を挟む区間は 1.6 倍ずつ広げる。
- BPV・YVBP は額面 100 当たりにせず、キャッシュフローの金額のまま返す。
- Macaulay デュレーションは複利の利回りでだけ計算でき、それ以外はエラー。

### 3.2 実装

- `interest_rate.rs`：`Compounding`（単利・複利・連続）と `InterestRate`（複利係数・割引係数）。混合の複利は未実装。
- `math/solver1d.rs`：QuantLib と同じ手順の解の区間探しと NewtonSafe。目的関数と微分を引数で受け取る、状態を持たない関数。
- `cashflow_analysis.rs`：利回りによる現在価値、デュレーション（Simple・Modified・Macaulay）、コンベクシティ、BPV、YVBP、内部収益率。
- `FixedRateBond`：`dirty_price`、`clean_price`、`yield_from_price`（クリーン・ダーティ）、`duration`、`convexity`、`basis_point_value`、`yield_value_basis_point`。
- 自動微分のための `Operand` trait はまだ入れていない。ここまでの計算は QuantLib の式（解析的な微分を含む）をそのまま再現するもので、自動微分の段階（AD-1）で入れる。

### 3.3 照合結果【実行照合済み】

2026-10-31、QuantLib R バインディング 1.42、`tools/golden/p2_bond_yields.R`、`cargo test --test golden_bond_yields`。

P2-1 の 1,500 本の債券それぞれについて、乱数（種を固定）で 6 通り、計 9,000 通りを選んだ：評価日、利回り（−0.5%〜12%）、単利・複利（年 1・2・4・12 回）・連続、日数計算 4 種類。価格はクリーン・ダーティを選び、計算した価格を 0〜3 ずらしてから利回りを解いた。

| 対象 | 件数 | 結果 |
|---|---|---|
| 価格・経過利子・デュレーション 3 種・コンベクシティ・BPV・YVBP | 67,491 個（QuantLib がエラーにした Macaulay の 4,509 件を除く） | 66,454 個が完全一致。1,037 個は最大で相対 2.5e-14 の差（許容誤差内） |
| QuantLib がエラーにした値（複利以外の Macaulay デュレーション 4,509 件、利回り 1 件） | 4,510 件 | Riemann もすべてエラー |
| 利回り（求根） | 8,999 件 | 8,936 件が完全一致。63 件は最大で 8.3e-14 の差（求根の精度 1e-10 の範囲内） |

**差の原因**：差が出たのは、複利（年 4 回・12 回）と連続複利だけで、単利と複利（年 1 回・2 回）はすべて完全一致した。同じ入力 20,000 組でべき乗・指数関数を R（MinGW の数学ライブラリー）と Rust（MSVC の数学ライブラリー）で比べると、べき乗 9 件、指数関数 59 件が最下位の 1 ビット違った。差はこの数学ライブラリーの違いによるもので、計算の手順は一致している。

**許容誤差**（仕様書 7.3 の初期案に従った）：単利の値は相対 1e-15、べき乗・指数関数を通る値（複利・連続）は相対 1e-12、利回りは求根の精度（絶対 1e-10）。


## 4. 割引カーブによる評価（P2-3）

### 4.1 QuantLib の仕様【ソース確認】

v1.42 のソースを読んで実装した（`70f240f` との差は確認していない）。

| 項目 | QuantLib v1.42 の仕様 | ソース |
|---|---|---|
| 時間 | 基準日からの年数（カーブの日数計算）。負の時間はエラー。外挿を許さなければ、最後の時間を超えるとエラー（`close_enough` で最後の時間と等しいものは可） | `termstructure.cpp`、`yieldtermstructure.cpp` |
| フラットカーブ | `FlatForward`：`InterestRate(r, 日数計算, 複利, 回数).discountFactor(t)`。最後の日付は 2199-12-31 | `flatforward.hpp` |
| ゼロカーブ | `ZeroCurve`：ゼロレートの線形補間。連続複利でない入力は、各点の時間で連続複利に換算する（最初の点は時間 0 なので 1/365 年で換算）。割引係数は `exp(-z t)`（t = 0 なら 1）。最後の点を超えると、最後の区間の傾きから求めた瞬間フォワードで平らに延ばす | `zerocurve.hpp`、`zeroyieldstructure.hpp` |
| 割引係数カーブ | `DiscountCurve`：割引係数の対数の線形補間。最初の割引係数は 1 でなければならない。最後の点を超えると、瞬間フォワードで平らに延ばす | `discountcurve.hpp`、`loginterpolation.hpp` |
| 線形補間 | 傾き `(y[i]-y[i-1])/dx`、値 `y[i] + (x-x[i]) s[i]`。範囲外は端の区間を使う | `linearinterpolation.hpp`、`interpolation.hpp` |
| ゼロスプレッド | `ZeroSpreadedTermStructure`：元のカーブのゼロレート（指定の複利、外挿あり）にスプレッドを足し、連続複利に換算する。基準日・日数計算・最後の日付は元のカーブのもの | `zerospreadedtermstructure.hpp` |
| ゼロレート | `zeroRate(t)`：t = 0 なら t = 0.0001 として、`impliedRate(1/discount(t), …, t)` | `yieldtermstructure.cpp`、`interestrate.cpp` |
| 債券の評価 | `DiscountingBondEngine`：NPV はカーブの基準日の現在価値（`Σ 額 × discount(支払日) ÷ discount(基準日)`、基準日以前の支払は除く）。受渡日の価値は受渡日について同じ計算。ダーティ価格 = 受渡日の価値 × 100 ÷ 額面（額面 0 なら 0）、クリーン価格 = ダーティ価格 − 経過利子。すべてのキャッシュフローが評価日以前なら満期済みで 0 | `discountingbondengine.cpp`、`bond.cpp`、`cashflows.cpp` |

### 4.2 実装

- `curves.rs`：`YieldCurve`（基準日、日数計算、外挿の可否、形）。形は列挙型で、フラット・ゼロ（線形）・割引係数（対数線形）・ゼロスプレッド（元のカーブを値として持つ）。`discount(日付)`、`discount_at(t, 外挿)`、`zero_rate_at(t, 複利, 回数, 外挿)`、`max_date`。
- `math/interpolation.rs`：線形補間 `Linear`。`math/solver1d.rs` に `close_enough` を追加。
- `interest_rate.rs`：`implied_rate`、`equivalent_rate`。
- `cashflow_analysis.rs`：`npv_on_curve`。`FixedRateBond::value_on_curve(カーブ, 評価日)` が NPV・受渡日の価値・ダーティ価格・クリーン価格を返す。
- エラーに `OutsideCurveRange`（外挿しないカーブの範囲外）を追加した。
- QuantLib との違い：オブザーバー・ハンドル・クォート・ジャンプはない。スプレッドは数値で、元のカーブは値として持つ。外挿の可否はカーブの値の一部。

### 4.3 照合結果【実行照合済み】

2026-10-31、QuantLib R バインディング 1.42、`tools/golden/p2_bond_curves.R`、`cargo test --test golden_bond_curves`。

P2-1 の 1,500 本の債券それぞれに、乱数（種を固定）で評価日と、評価日を基準日とするカーブを 1 本選んだ：ゼロカーブ 738 本（連続 381・複利 186・単利 171）、割引係数カーブ 483 本、フラットカーブ 279 本、ゼロスプレッド 312 本（元のカーブはゼロまたは割引係数）。日数計算 4 種類。572 本は外挿を許し、一部のカーブは満期より前で終わる（範囲外のエラーを確かめるため）。

| 対象 | 件数 | 結果 |
|---|---|---|
| カーブの割引係数（基準日から満期の約 8 年後までの日付） | 10,500 件（うち QuantLib のエラー 3,276 件） | エラーはすべて一致（原因はすべて外挿しないカーブの最後の時間を超えたこと。Riemann は `OutsideCurveRange`）。値 7,224 件のうち 7,063 件が完全一致、161 件は最大で相対 1.5e-14 の差（許容誤差内） |
| 債券の NPV・クリーン価格・ダーティ価格 | 1,500 本（うち QuantLib のエラー 481 本） | エラーはすべて一致（原因は同じく最後の時間を超えたこと）。値 3,057 個のうち 2,960 個が完全一致、97 個は最大で相対 2.5e-15 の差（許容誤差内） |

**許容誤差**（3.3 節と同じ考え方）：フラットカーブの単利は相対 1e-15、べき乗・指数関数・対数関数を通る値は相対 1e-12。差の原因は数学ライブラリーの最下位ビットの違い（3.3 節）と考えられるが、カーブについては個別に確かめていない。

**エラーの原因**：照合用 CSV にはエラーの有無だけを書いている。原因を確かめるため、同じ種で生成スクリプトを再実行して QuantLib のメッセージを記録した（値と ERROR の位置は CSV と完全に同じ）。メッセージは 3,276 件・481 本すべて `time (…) is past max curve time (…)` で、外挿を許さないカーブが満期より前で終わる場合、または満期の後の日付を調べた場合として想定したものだった。テストは、QuantLib のエラーに対して Riemann が `OutsideCurveRange` を返すことまで確かめる。

## 5. 日本式の利回り（P2-4）

### 5.1 採用した仕様【ソース確認】

日本式の債券計算は、既存の VBA 互換の定義を引き継ぐ。VBA の原本は手元になく、その定義を移した GaussQuant の `R/bond_yen_GQL.R`（コミット `4ff081c`「Add VBA-compatible yen bond analytics」、2026-09-13）を仕様の正とした。GaussQuant にこれらの関数のテストはない。

| 項目 | 定義（GaussQuant と同じ） |
|---|---|
| 残存年数 | 受渡日と満期日の暦年の差が 1 より大きければ、「暦年の差 − 1」に、月日を 1990 年（受渡日）と 1991 年（満期日）に置いた日付の間の日数 ÷ 365 を足す（2 月 29 日は 2 月 28 日とする。閏日は数えない）。それ以外は実日数 ÷ 365。小数第 7 位未満を切り捨て |
| 単利の価格 | `(R + C T) / (1 + Y T / 100)`。既定で小数第 3 位未満を切り捨て |
| 単利利回り | 上の価格式をニュートン法で解く。初期値 `100 / T × ((R + C T) / P − 1)`、価格差が `10^-(桁数+1)` 未満になった反復の更新後の値を返し、既定で小数第 7 位未満を切り捨て。最大 100 回 |
| 複利の価格 | 利払い回数 f、複利回数 m、`α = (1 + Y / (100 m))^(−m/f)` として、クーポン `C / f` の等比級数と償還の割引。Y = 0 は別の式（f = m = 2 は閉じた式） |
| 複利利回り | 単利と同じ初期値・ニュートン法で、微分は解析的な dP/dY |
| リスク指標 | 利回りは % 単位。BPV（円）= −dP/dY ÷ 100、BPV（銭）= −dP/dY、修正デュレーション = −100 dP/dY ÷ ダーティ価格、コンベクシティ = 10000 d²P/dY² ÷ ダーティ価格 |

**市場慣行の説明との違い**：二次情報（計算解説サイト）には「満期まで 1 年以上なら閏日を考慮しない、1 年未満なら考慮する」という説明がある。GaussQuant は暦年の差で分岐するため、暦年の差がちょうど 1 で、残存が 1 年以上あり、間に 2 月 29 日を含む場合に、残存日数が 1 日多くなる（例：2023-04-01 から 2024-10-01 は、GaussQuant が 549 / 365 = 1.5041095、上の説明なら 1 + 183 / 365 = 1.5013698）。照合用の 1,200 件では 30 件がこれに当たった。この説明は日本証券業協会などの一次資料で確認できていないため、採用しなかった。VBA の原本で「2 月 29 日を 2 月 28 日とする」扱いが同じかどうか（VBA の `DateSerial(1990, 2, 29)` は 3 月 1 日になる）も確認できていない。

### 5.2 実装

- `yen_bond.rs`：`remaining_years`、`price_from_simple_rate`、`simple_rate_from_price`、`price_from_compound_yield`、`compound_yield_from_price`、`risk_from_simple_rate`、`risk_from_compound_yield`（`YenBondRisk`）、`truncate_decimal`。式は残存年数 T を引数に取り、日付からの T は `remaining_years` で求める。
- 計算の順序、切り捨て、ニュートン法の止め方、R の `^`（底が 1 か指数が 0 なら 1、指数 2 は `x * x`）を GaussQuant と同じにした。
- 利払い回数・複利回数は正の整数（GaussQuant は正の実数を受け付ける）。

### 5.3 照合結果【実行照合済み】

2026-10-31、GaussQuant 2026.6.18.1（ソースはコミット `c08fdb1`。インストール済みの `bond_yen_GQL.R` の関数 12 個が、ソースと同じであることを確かめた）、`tools/golden/p2_yen_bonds.R`、`cargo test --test golden_yen_bonds`。

乱数（種を固定）で 1,200 件を選んだ：受渡日（2 月 29 日・2 月末・月末を含む）、満期（1 年前後・応当日ちょうど・40 年まで・受渡日と同日）、クーポン 0〜7.5%、償還 100・101.5、単利 −0.3〜12%、複利 −0.4〜6.515%（0 を含む）、利払い回数 1・2・4、複利回数 1・2・4・12、経過利子 3 種類。利回りを解く価格は、単利から求めた切り捨て後の価格（LagrangeFinance II-1 と同じ流れ）を 0〜2.5 ずらしたもの。

| 対象 | 件数 | 結果 |
|---|---|---|
| 残存年数 | 1,200 件 | すべて完全一致 |
| 単利・複利の価格（切り捨てなし・小数第 3 位） | 4,800 個 | 4,799 個が完全一致、1 個は相対 1.6e-16 の差 |
| 単利利回り・複利利回り（小数第 7 位） | 各 1,179 件 | すべて完全一致 |
| 利回りのエラー | 各 21 件 | すべて一致（下記） |
| リスク指標（単利・複利、各 6 項目） | 14,400 個 | 1 階微分・BPV と単利の価格・修正デュレーションはすべて完全一致。2 階微分とコンベクシティの 623 個、複利の価格と修正デュレーションの各 1 個、計 625 個は最大で相対 7.1e-15 の差（許容誤差内） |

**エラーの原因**：利回りのエラー 21 件は、単利・複利とも同じ 21 件で、すべて受渡日と満期日が同じ日（残存年数 0）だった。単利は「`price` and the time to maturity must be positive.」、複利は初期値が無限大になり「The compound yield is outside its valid domain.」で止まる。どちらも残存 0 の入力に対して想定どおりのエラーである。

**差の原因（未確認の推定）**：差が出たのは 3 乗や実数のべき乗を通る値だけで、切り捨てた価格と利回りには影響がなかった。Windows 版の R はべき乗を拡張精度（`powl`）で計算するので、数学ライブラリーの最下位ビットの違いによると考えられるが、個別には確かめていない。

**許容誤差**：残存年数は完全一致、単利の値は相対 1e-15、複利の値は相対 1e-12。
